# Testing strategy — Mixlumo

Mixlumo is a **single-user desktop web app**: a FastAPI server bound to
`127.0.0.1`, a vanilla-JS single-page UI, and an engine that runs AI separation models
(BS-RoFormer, Mel-Band RoFormer, Demucs) on the local GPU. There are no accounts, no
database, no cloud storage and no billing. This document maps the project's testing
policy onto that architecture and states plainly which parts do not apply.

## How to run

```powershell
.\run_tests.ps1              # lint, types, unit, integration, e2e (Chromium + Edge), security, build
.\run_tests.ps1 -Gpu         # + real-model GPU tests and the GPU browser journey
.\run_tests.ps1 -Benchmark   # + audio-quality benchmark against MUSDB18 reference stems
```

`run_tests.ps1` is the CI pipeline for this project (there is no Git remote, so it runs
locally). It exits non-zero on any failure; a build that fails it must not be used.
Non-GPU stages run with `CUDA_VISIBLE_DEVICES=-1` so they never compete with a running
separation for the 4 GB GPU.

## Test layers

| Layer | Tool | Location | What it proves |
|---|---|---|---|
| Unit | pytest | `tests/test_engine.py` | Audio decode/encode, every tool's output (duration, sample rate, channels, clipping, pitch, fades), validation, progress mapping |
| Integration (API) | pytest + httpx (`fastapi.testclient`) | `tests/test_api.py` | Every endpoint, request validation, upload validation, job queue order, progress/ETA, error reporting, file serving, cleanup |
| Security | pytest + ruff `S` (bandit) rules + pip-audit | `tests/test_api.py`, `run_tests.ps1` | MIME spoofing, size limit, path traversal (upload names, stem paths, static files, folder opening), localhost-only binding, no secret leakage, dependency CVEs |
| GPU worker | pytest (`-m gpu`) | `tests/test_gpu.py` | Real inference for all engines, output format, live progress, GPU memory release, engine switching, distortion |
| Audio quality | custom benchmark | `benchmarks/audio_quality.py` | SDR, leakage, duration, sample rate, channels, clipping, speed, GPU memory against reference stems |
| Frontend e2e | Playwright (pytest-playwright) | `tests/e2e/` | All user journeys, upload UI, waveform, player, mixer, loading/failure states, responsive layout, accessibility, browser compatibility |
| Light load | pytest + threads | `tests/test_api.py::test_concurrent_requests` | 50 parallel requests (uploads + API) with a p95 latency bound |

GPU tests are skipped automatically, with the reason printed, when there is no CUDA GPU
or another process is already using more than 1.2 GB of GPU memory.

## Test data

- **Synthetic fixtures** (`tests/conftest.py`): tones, an A-major triad, a 120 BPM click
  track, a video file, and malicious files (text named `.mp3`, PNG named `.wav`, empty
  file). All generated by ffmpeg at test time, so there are no licensing questions.
- **Reference stems:** MUSDB18 7-second excerpts, test split (Zenodo record 3270814),
  licensed for research/non-commercial use. Stored outside the project in
  `~/.audiostudio/testdata`. No customer or personal audio is used by any automated test.
- Every test writes to temporary folders. `AUDIO_STUDIO_OUT` and `AUDIO_STUDIO_UPLOADS`
  are redirected before the app modules are imported.

## Audio-quality acceptance

Separation quality is accepted on **objective metrics only** (median over tracks):

| Model | Vocals SDR | Accompaniment SDR | Other |
|---|---|---|---|
| BS-RoFormer | ≥ 8 dB | ≥ 13 dB | |
| Mel-Band RoFormer | ≥ 7 dB | ≥ 12 dB | |
| Demucs 2-stem | ≥ 6 dB | ≥ 11 dB | |
| Demucs 4-stem | ≥ 6 dB | | drums ≥ 5 dB, bass ≥ 3 dB |

All configurations must also give 44.1 kHz stereo output, output length equal to input
(±1 sample), zero clipped samples, peak GPU memory ≤ 3800 MB, and monotonic progress
with at least 3 updates. Results: `docs/audio-quality-benchmarks.md`.

## Coverage targets

- Backend (engine + server): **85 %** branch coverage, enforced by stage 9 of the gate
  over unit + integration + GPU tests combined. Model-wrapper logic (OOM fallback,
  `sys.exit` handling, caching) is also unit-tested with stand-in models, so the CPU
  stages alone reach 99 %.
- The gate verdict is **PASS** only if no stage failed, skipped or was not run.
  Without `-Gpu` the verdict is **INCOMPLETE**, never PASS.
- Every API endpoint has at least one integration test; every main user journey has an
  e2e test.
- Coverage is a floor, not proof of quality: the benchmark and e2e tests carry the
  behavioural guarantees.

## Policy sections that do not apply (and why)

| Policy item | Status | Reason |
|---|---|---|
| PostgreSQL test database | N/A | No database; job state is in memory for one local user |
| Authentication, authorization, unauthorized project access, auth bypass | N/A | No accounts. Instead the server binds only to `127.0.0.1` (tested), so other machines cannot reach it |
| Subscription and credit calculations | N/A | No billing |
| Object storage, signed URLs and their expiry | N/A | Files live on the local disk; access is limited to the output folder (path-traversal tests) |
| Redis queues | N/A | An in-process single-worker queue (`ThreadPoolExecutor(1)`) is tested for ordering and isolation |
| Worker retries, database failures, scale-to-zero | N/A | No distributed workers or database. Worker failure → job `error` state is tested. GPU out-of-memory → automatic CPU fallback in Demucs |
| GPU timeout | Not implemented | Local jobs may legitimately take 10+ minutes; there is no timeout to test. Listed as a known gap in `progress.md` |
| API rate limits | N/A | Single local user; a light concurrency test checks the server stays responsive |
| Vitest / React Testing Library | N/A | No React or build step; the UI is one HTML file. Playwright covers component behaviour in a real browser |
| Locust | Replaced | A 50-request threaded test stands in. A Locust farm would measure nothing useful for one local user |
| Firefox | Blocked | Playwright's Firefox fails to start on this PC (missing Visual C++ runtime: "side-by-side configuration is incorrect"). Chromium and Microsoft Edge are tested |
| Cost per processed audio minute | Reported as time | Local hardware has no per-minute cost; the benchmark reports seconds of GPU time per minute of audio |
